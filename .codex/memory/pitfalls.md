# Failure Patterns

## Windows Bash Test Sensitivity

- Symptom:
  - Bash-based tests may fail to run cleanly in this Windows environment even when the scripts themselves are not obviously broken.
- Cause:
  - Environment-level Bash/service constraints rather than confirmed logic failure in the repo.
- Workaround:
  - Report the environment blocker explicitly and avoid overstating verification status.
- Confidence:
  - Medium

## Generated Handoff Files Look Like Normal Docs

- Symptom:
  - `AI_HANDOFF.md` and `RESUME_PROMPT.md` can appear in the working tree and be mistaken for maintained source documentation.
- Cause:
  - They are generated by hook/session behavior and live in the repo root.
- Workaround:
  - Treat them as runtime artifacts unless the user explicitly asks to regenerate or preserve them.
- Confidence:
  - High

## Historical Docs Can Drift Behind the Code

- Symptom:
  - Older plan/status docs may describe thresholds, architecture, or repo naming that no longer match current code and current decisions.
- Cause:
  - The project evolved quickly across implementation and collaboration phases.
- Workaround:
  - Prefer recent code, current branch state, recent commits, and active dated plan docs when establishing current truth.
- Confidence:
  - High
